## What was reused

The db2 taps, filter normalization, and elementary autocorrelation proof
pattern are adapted from the predecessor's MIT-licensed Solution.lean and
TWS/DaubechiesOpNorm.lean. Original attribution is preserved in NOTICE and
third_party/tws-repro-MIT.txt. They are not the new operator-norm proof.

The new finite-group convolution operator, exact norm argument, sign witness,
folding argument, tensorization and their db2 assembly are supplied in full
in this candidate's Solution.lean. The old TWS/Skeleton.lean is not included.

The Lake manifest is based on the official template and retains all resolved
dependency revisions. Only the project name and the top-level Mathlib
`inputRev` spelling were changed to match the explicit immutable Lakefile pin.
The manifest has not been regenerated by Lake in this environment.

The verifier script is copied from the stated official template revision.
The CI workflow is adapted to this smaller project and uses its pinned action
revisions. It has since been run. The runs and the commits they cover are
listed in `docs/VERIFICATION.md`. A workflow run is not a Palomar review.

## Repository role

The old submission was a thin wrapper, and its missing structured relationship
was a real defect. This replacement proposes that tws-palomar become the home
of the substantive new proof development. The ordinary metadata shape omits
`repository`; full source-based provenance remains in `sources` and
`related_formalizations`. This classification applies only to the replacement
architecture, not retrospectively to the rejected wrapper.

If the maintainer relocates the new proofs to tws-repro, this classification
must change and the wrapper must identify the actual new underlying commit.

## Correction after the preparation container

The preparation container could not start Lean. On 2026-10-17 the same
candidate was elaborated locally with Lean `v4.35.0-rc2`, commit
`11acb17ec6b07a8f9e9173e6845197929540936b`, on arm64-apple-darwin, against
Mathlib `065356127b1dc0016f66b7283ce0ce2c4055aa55`. Two proof scripts in
`Solution.lean` were adjusted to that API. At that step the development had
seven selected statements, and those seven statements were not changed by
the API edits. `lake build` succeeded, and `#print axioms` on
those theorems reports only `propext`, `Classical.choice` and `Quot.sound`.
The official script `scripts/verify-comparator.sh` was not run, because it
requires bubblewrap. At that step this tree had no git commit;
`docs/evidence/SHA256SUMS.txt` identifies the files that were checked.

## Cascade levels 1, 2 and 3

On the same date, three selected statements were added:
`cascade_level1_opNorm`, `cascade_level2_opNorm` and `cascade_level3_opNorm`.
They are finite evaluations of the undecimated recurrence. Together with the
previous eleven, that was the fourteen-statement list accepted by the
unsandboxed Darwin replay of that date. `scripts/verify-comparator.sh` did
not run on that machine, because bubblewrap is absent.

Commit `7295c00346b8295d4857a3b2f24a6ad0c037d256` later adds the closed form
for every level. The exposition is `docs/CASCADE_THEOREM.md`. The literature
comparison, which does not settle priority, is `docs/RELATED_WORK.md`.
The sandboxed check of the proof commit is GitHub Actions run 39093434816.
A later revision changes only comments in `Challenge.lean` and
`Solution.lean`. Its local Darwin recheck, without sandbox, is recorded in
`docs/VERIFICATION.md`. That recheck is not run 39093434816 or 39093722987.
This directory is the repository root. Palomar should receive the full SHA
of the commit the maintainer chooses to submit, with `comparator.json` at
the root. This file does not name that SHA in advance of the commit.
